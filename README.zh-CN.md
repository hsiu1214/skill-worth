# skill-worth

**这个 AI 技能，到底值不值得装？**

[English](README.md) · [报告样例](examples/report-sample.html)

---

安全扫描器告诉你一个 skill 是不是**危险**的。没有一个告诉你它是不是**空的**。

前者已经有很好的工具了——[NVIDIA SkillSpector](https://github.com/NVIDIA/SkillSpector)（68 种漏洞模式、YARA、污点追踪）、[Snyk agent-scan](https://github.com/snyk/agent-scan)、[Cisco skill-scanner](https://github.com/cisco-ai-defense/skill-scanner)。该用就用。但这个工具问的是另一个问题，而它们全都会给绿灯：

> 一个 skill 可以完全安全——没有恶意代码、没有外连、没有窃取密钥——同时什么都不做。

`skill-worth` 找的就是这一类。

## 问题在哪

在一批 30 个热门市集 skill（安装量均 ≥500）的抽样里，**3 个是空的**，而这 3 个合计被安装了 **104,762 次**。三个的破绽一模一样：作者在 SKILL.md 里自己写着，实现「之后再补」。

空壳不是安全事故。它只是浪费上下文、浪费安装量，然后让用户默默得出「AI 技能好像没什么用」的结论。

## 查什么

五个维度，加权 100 分：

| 维度 | 权重 | 问的问题 |
|---|---|---|
| **实质功能** | 40 | 有没有能跑的代码？如果是文档，步骤/清单/示例是否完整？ |
| **宣称为实** | 25 | 说的和做的一致吗？提到的文件真的存在吗？ |
| **说明清楚** | 15 | 一句话能说清用途吗？触发词会不会过宽？ |
| **安全** | 10 | 删除操作、动态执行、硬编码密钥 |
| **维护** | 10 | 结构是否完整、有没有套模板的空话、有没有死引用 |

**四条硬伤直接判「别装」**（不看总分）：

1. 作者自己写明还没实作（`"接入真实运行时补全"` 这类）
2. 教你调用一个不存在的工具（写 `web_fetch(...)`，实际工具叫 `WebFetch`）
3. 声称要动手做事（爬取、批处理、调 API），却一个代码文件都没有
4. 有代码文件，但里面全是 `pass` / `TODO` / 空函数

## 最难的地方：没有代码 ≠ 没用

所有粗糙的检查器都栽在这里。一份检查清单、一套写作方法、一个诊断流程——它们的价值全在文字里，不需要代码，而且真的管用。

所以扫描器要能分开两类：

- **动手型**：「爬取 16 个引擎」「下载并合并」「调用 API」。没有代码 → 空壳。
- **知识型**：「这里是审查 skill 的方法」「这里是评分标准」。步骤、清单、示例齐全 → 成立。

判错任何一边，这个工具就没用了。扫描器两边都被实测过。

## 安装

零依赖，Python 3.8+。

```bash
git clone https://github.com/hsiu1214/skill-worth.git
cd skill-worth
```

## 用法

**装之前，评估一个 skill：**

```bash
python scripts/scan.py --target /path/to/some-skill --out sk.json
python scripts/render.py sk.json report.html
```

**盘点已经装好的全部：**

```bash
python scripts/scan.py --all --out sk.json
python scripts/render.py sk.json report.html
```

**抽样看市集整体情况**（会下载并实测热门 skill，30 个约 40 秒）：

```bash
python scripts/market.py --top 30 --min-installs 500 --out market.json
python scripts/render.py sk.json report.html --market market.json
```

输出是一份自包含的 HTML——不引 CDN、不用框架、离线可开、能直接打印、手机上也看得清。

## 结果长什么样

三档，每档都带人话理由和可展开的证据：

```
值得装   97   有 3 个代码文件共 775 行；提到的 2 个附件都在
看你要什么 61   没有代码，但步骤、清单、示例写全了——是份文档，不是工具
别装     28   作者自己写明还没实作；3 处套模板的空话；0 个代码文件
```

生成报告前会剥掉绝对路径和命名空间，实测零泄漏——报告就是拿去发给别人的。

## 实测过的案例

| Skill | 安装量 | 判定 |
|---|---|---|
| `multi-search-engine` | 204 万 | **别装**——宣称 16 个引擎，零脚本，教的是不存在的工具 |
| `summarize` | 4.6 万 | **别装**——3.5KB，作者自承是自动生成的骨架 |
| `skill-vetter` | 30.7 万（真版本） | **值得装**——140 行纯文档，但 4 步审查协议是完整的 |
| `self-improving-agent` | 8.6 万 | **值得装**——5 个真代码文件，hook 只做内存注入，零外连 |

市集里安装量最高的两个 skill 是空的。**安装量和质量基本无关**——它只跟「名字有没有说中需求」相关。

## 局限

- **只做静态分析**，从不执行被扫描的代码
- **只看有没有，不看好不好**——能判断实现是否存在，判断不了实现写得对不对
- **短小精悍的 skill 会被低估**——简洁在文本密度面前看起来像单薄
- **同名不等于同包**——市集可能在同一 slug、同一版本号下给出不同内容。结论只代表实际扫到的那份，报告里会写明口径
